# خارطة التنفيذ (من المواصفة §17)

قاعدة: لا نبدأ كل الوحدات بالتوازي قبل تثبيت نماذج البيانات الأساسية (الملكية، الصفقة، القيود).

| المرحلة | النطاق | الحالة |
|---|---|---|
| 0 | تثبيت المتطلبات (قوالب، قيم قانونية/ضريبية، حدود الموافقات) | يتطلب إدخالاً من الإدارة — مُهيّأ كإعدادات |
| 1 | الأساس التقني: Auth+MFA، RBAC، Audit، إعدادات الكيان، ترقيم المستندات، API/OpenAPI، PWA/RTL | قيد التنفيذ |
| 2 | CRM والكتالوج وقوائم الأسعار | |
| 3 | العروض (Snapshot)، الموافقات، الصفقات وأوامر البيع، طلبات المورد | |
| 4 | الشحن، المواقع، الملكية/الحيازة، المخزون والحركات، الأرقام التسلسلية، الجرد | |
| 5 | المحاسبة، الذمم، الدفعات والتوزيع، الصناديق/البنوك، العملات | |
| 6 | ملفات الأجهزة، الضمان، الصيانة | |
| 7 | الوثائق، OCR/AI Gateway، الإشعارات (بريد/WhatsApp/Push) | |
| 8 | التقارير ولوحات التحكم، UAT، الترحيل، الإطلاق | |

## تعريف الإنجاز لكل مرحلة
1. نماذج + migrations + قيود DB.
2. خدمات الأعمال (services) مع معاملات وidempotency حيث يلزم.
3. API مع صلاحيات على مستوى الإجراء/السجل/الحقل.
4. اختبارات وحدة وتكامل وRBAC.
5. واجهة (عربي RTL أولاً) + توثيق OpenAPI.
